# Garage Implementation Plan (v2.11)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline).

**Goal:** buyable Peugeot 206 WRC, four upgrades per car, a garage screen with a 3D preview, the selected car used in play.
**Architecture:** data in `vehicles.json` + `VehicleSpec`, pure `game/garage.rs` (upgrade maths, prices), profile persistence, world/game take a spec, a generated `rally` model style, a garage scene mode in the engine, Kotlin `GarageActivity`.
**Spec:** docs/superpowers/specs/2026-10-14-garage-design.md

## Global Constraints
- No external assets; the reference file is not used. Aircraft untouched. Version 2.11.0 (versionCode 22). Trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. EN+RU strings. Device checks short, Termux in front at the end, never touch the user's profile.json (use a separate test profile in the app files for device checks); sound plays during device tests.

## Review Focus
- Profile: old files, unknown ids, `selected` not owned, saturating money, no negative or overflowing prices, buy atomicity (money and level change together).
- The selected car reaching every world creation path (new level, mission start, restart, place_* helpers, Retry) and the renderer rebuilding meshes exactly once per change.
- Garage scene: no input effects, no mission HUD side effects, leaving the activity stops the engine, a missing/invalid index.
- The Peugeot: stability on slopes and jumps, spec numbers in `vehicles.json` matching the docs, the CoM guard for all cars.

### Task 1: Car data (Peugeot spec)
**Files:** `rust/vehicles.json`, `rust/src/game/{params,vehicle}.rs` + tests, `docs/vehicles.md`.
**Interfaces:** Produces `VehicleSpec{ style: CarStyle (Suv|Rally), price: u32, upgrade_cost: u32 }`, `Params::car_ids() -> Vec<String>` (file order), `VehicleSpec::all() -> Vec<(String, VehicleSpec)>`.
- [ ] Tests (RED first): params parse `model`/`price`/`upgrade_cost` with defaults (suv, 0, 300) and errors for bad values (`"model": "boat"`, negative price); the embedded file lists `offroader` then `peugeot206` with the numbers of the spec; the centre-of-mass guard (`half_track / (rest + radius - y) > mu * 1.15`) holds for every car; the Peugeot rests on flat ground (y within its rest height, up.y > 0.99), out-accelerates the off-roader (speed after 5 s of full throttle higher), does not roll in the hard-turn matrix of `hard_turns_on_flat_ground_do_not_roll_the_car` (generalise the helper to take a spec) and reaches reverse speed above 5 m/s.
- [ ] Implement: add the fields (defaults when missing), the JSON entry, the `docs/vehicles.md` rows (EN+RU: `model`, `price`, `upgrade_cost`).
- [ ] `cargo test --lib`; commit `feat(game): peugeot206 car data`.

### Task 2: Garage logic and profile
**Files:** create `rust/src/game/garage.rs` (+tests); modify `meta.rs` (+tests), `mod.rs`, `api.rs` (garage info/actions helpers).
**Interfaces:** Produces `garage::{Upgrade{Engine,Tyres,Suspension,Brakes} (ALL), MAX_LEVEL=3, apply(&VehicleSpec, [u8;4]) -> VehicleSpec, upgrade_price(&VehicleSpec, current_level:u8) -> Option<u32>}`, `Profile{ garage: Garage }` with `Garage{ selected: String, cars: Vec<(String,[u8;4])> }`, `Profile::{owns(id), levels(id)->[u8;4], buy_car(id)->bool, buy_upgrade(id, Upgrade)->bool, select(id)->bool, selected_spec()->VehicleSpec}`, `api::{garage_info(path, fresh)->Vec<f32>, garage_buy_car(path, i)->bool, garage_buy_upgrade(path, i, u)->bool, garage_select(path, i)->bool}`.
- [ ] Tests (RED first): `apply` level 0 is identity; only the documented fields change, by the documented factors (engine_force x1.08/1.16/1.25, max_speed x1.03/1.06/1.09, mu x1.05/1.10/1.15, spring and damper x1.1/1.2/1.3, brake_force x1.2/1.4/1.6) and are monotonic; prices `upgrade_cost * (1, 2, 4)`, `None` at level 3; `Profile::new` owns only the off-roader and selects it; `buy_car` needs the money (reduces it exactly by the price, repeats return false); `select` needs ownership; `buy_upgrade` needs ownership, money and level < 3, and is atomic (money and level change together); money never underflows; JSON round trip keeps garage state; an old file without `garage` loads as off-roader only; an unknown car id in the file is dropped; a selected id that is not owned falls back to the off-roader; `selected_spec` returns the spec with upgrades applied; the `api` helpers act on a profile file by car index (file order) and return false for bad indices.
- [ ] Implement; profile writes `garage` (version stays 1).
- [ ] `cargo test --lib`; commit `feat(game): garage logic and profile`.

### Task 3: World and game use the selected car; garage scene
